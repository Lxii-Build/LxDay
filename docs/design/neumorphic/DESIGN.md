## 1. 最终设计决定

采用「柔光新拟态」而非复古皮革／金属写实拟物：同色系基底、统一左上光源、短距离双阴影、可感知按压、少量玻璃导航。保留 miuix 操作习惯、品牌蓝、现有圆角与中文文案。

全 UI 统一的是材质语言，不是每一个文本行都凸起。信息密集区保持平面，交互区形成微凸或内凹。APP 亲密、轻松；后台安静、可扫描；二者共享颜色、光源和语义，不共享所有布局和密度。

### 1.1 已确定，不让接手 AI 自行发挥

- 主导航保留四项：主页、待办、发现、我的。主页可在视觉稿中使用副标题“此刻”，首轮不随意改路由或标签。
- 音乐保持发现入口，但增加应用级迷你播放条与全屏播放页。不增加第五个 tab。
- 列表仍用 `KernelScreen`；播放器使用独立非列表布局，不改成网页嵌入播放器。
- 拟态表面不替代 `LxButton`、`LxConfirmDialog`、`LxFormDialog` 的语义和行为。
- 基础圆角卡片16、按钮16、缩略图8。主播放键为放大的圆角方形，不另造与仓库冲突的圆形普通按钮体系。头像仍可圆形。
- 固定品牌蓝，不随封面／壁纸改变全局主色；封面不用于全屏动态模糊背景。
- 不做持续旋转唱片、粒子、音频可视化、呼吸光，也不增加系统灵动岛、悬浮窗或新权限。
- 后台沿用 Vue、Element Plus、ArtTable、现有主题和路由，不引入 Bootstrap、Tailwind UI 模板、React 或整套拟态组件依赖。
- 除Draft1.2明确新增的角色资源库接口/存储/必要迁移外，不新增其他服务端能力。缺失的指标、队列协议、同步能力必须标“后续提案”，不能用假数据进入生产。

### 1.2 本方案主动排除

不做音乐下载／音源破解、社交广场、AI 推荐、相册人脸识别、管理端私人照片墙、全站实时监控大屏。不是因为不能画，而是与现有产品和授权范围不符。

| 第一方来源 | 观察／技术依据 | 林曦采用 | 林曦不采用 |

| [Neumorphism.io](https://neumorphism.io/) | 可控制颜色、距离、模糊、强度和形状；实测切换 Pressed 后生成 `inset` 双阴影 | 一处 token 控制高光与暗影；Raised/Inset 状态成对设计 | 默认20px偏移、60px模糊、50px圆角不直接搬到手机按钮 |

| [MDN box-shadow](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/box-shadow) | 支持多层阴影、偏移、模糊、spread 与 inset | 后台 CSS 变量管理双阴影 | 不写几百处分散的 box-shadow，不用图片模拟普通按钮 |
| [Element Plus 主题指南](https://element-plus.org/en-US/guide/theming.html) | 支持主题变量与样式定制 | 覆盖现有主题变量并局部适配复杂控件 | 不全局给所有 div、button 或 el-card 叠阴影 |
| [miuix 官方仓库](https://github.com/compose-miuix-ui/miuix) | Compose Multiplatform UI 库 | 保留现有 miuix 0.9.3 与图标体系 | 不因官网新版本例子顺手升级本项目 |
| [W3C 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) | 普通文本4.5:1、大文本3:1；识别控件／状态所必需的非文字视觉信息通常需3:1 | 标签、图标、边界与状态共同可辨，不把弱阴影作为唯一信号 | 不声称只要有阴影、字号加粗或加一个焦点圈就自动合规 |

### 2.1 如何真正做出拟态，而不只是普通阴影卡片

1. 基底不是纯白，微凸表面与邻近背景相同或接近。
2. 左上高光、右下暗影为一组；内凹时改为内部阴影，光源不改变。
3. 光影尺度随组件尺寸分档，绝不把大卡片阴影原样用于小图标。
4. 普通内容没有按压动画；只有交互控件在按下时收低高度。
5. 选中不等于按下：选中需要持久标识（文字／勾选／位置），按下是短暂触觉反馈。
6. 暗色不用纯黑配纯白高光；提高表面亮度和边界可见度，降低高光不透明度。

这些是本项目据研究制定的设计决定，不是任何参考站替我们给出的质量保证。

**已发现的既有约束冲突：** 白字对品牌蓝约4.03:1，白字对品牌红约3.91:1（sRGB公式计算），均未达到普通小文本4.5:1。不能写“现有蓝红白字全部达到 AA”。首轮保持 AGENTS 品牌规则，不擅自改色；将其登记为需用户确认的无障碍例外。可提交两种候选：①保留品牌色，关键文字按钮使用满足大文本条件的字号／字重，按平台实测；②经用户批准再增设更深的可访问操作色，品牌色保留在品牌资产。不能靠阴影修复文字对比。本 HTML 示意也不宣称已全面 AA。

### 4.2 材质档位

统一左上光源。表中偏移／模糊为 CSS px 初值，Android 对应 dp 设计值，跨渲染器不保证同数值同观感；spread 默认0。

| 档位 | 浅色阴影 | 暗色阴影 | 使用限制 |
| --- | --- | --- | --- |
| Flat | 无 | 无 | 表格、歌曲行、歌词、照片网格 |
| Raised | `4 4 10 rgba(163,177,196,.42)` + `-4 -4 10 rgba(255,255,255,.86)` | `3 3 8 rgba(0,0,0,.28)` + `-2 -2 6 rgba(255,255,255,.04)` | 卡片与实体控件；不要套娃 |
| Inset | `inset 2 2 5 rgba(163,177,196,.48)` + `inset -2 -2 5 rgba(255,255,255,.88)` | `inset 2 2 5 rgba(0,0,0,.32)` + `inset -1 -1 3 rgba(255,255,255,.035)` | 搜索、进度槽、选中槽 |
| Floating | Raised + `0 10 24 rgba(33,48,70,.12)` | `0 8 20 rgba(0,0,0,.28)`＋内部顶边`0 1 0 rgba(255,255,255,.04)` | 播放条、弹层；避免全页面使用 |
| Glass | 沿用现有 FloatingBottomBar 材质实现 | 同现有主题分支 | 导航专用，不扩散到所有卡片 |

有色按钮使用语义底色与较轻的中性投影，不叠亮白大光斑改变颜色。光影绝不盖住文本。降低动效或高对比模式时去掉装饰阴影，保留实色、轮廓、语义。

### 4.3 字体、布局、尺寸

- 字体沿用系统中文无衬线，不额外下载字体；Android sp、网页 rem，不能禁用系统字体缩放。
- APP 页标题24/32、区块标题18/26、正文16/24、辅助14/20、时间12/18；斜杠后为行高。既有顶栏若受 miuix API 限制，以不裁字优先。
- 后台页标题24/32、区块18/26、表格14/22、辅助12/18；数据指标32/40，数值用等宽数字，不把全站正文换成等宽字体。
- 间距4、8、12、16、24、32；APP标准页边16、卡片内16，区块间24，关联行间8～12。
- APP 列表行至少64dp，双行内容按需增高；按钮触达至少48×48dp，由组件内部保证。
- 后台桌面输入／按钮最小40px，触屏断点至少48px；表格行基础52px，内容多时增高，不用固定高度裁切。
- APP 以390dp宽画基准，验证320/360/390/412/600/840；后台基准1440px，验证360/390/768/1024/1440/1920。
- 图片保持比例；相册封面／网格必须有灰底和失败占位。仅播放器主封面按小屏高度缩放。

### 4.4 交互状态（全组件必须实现）

| 状态 | 表现 | 行为 |
| --- | --- | --- |
| Default | Raised或Flat，标签清楚 | 不动时无循环动画 |
| Pressed | 阴影收小、内部轻压暗，可位移1dp | 80ms按下、120ms恢复；不改变布局尺寸 |
| Selected | 内凹槽＋勾选／蓝色标记＋语义状态 | 切换后持续存在，不靠阴影方向辨别 |
| Focus | 与表面有足够对比的2px/dp轮廓，外偏2 | 键盘焦点可见，不用hover替代 |
| Disabled | 去交互、降低装饰强度 | 仍说明为什么不可用；不是透明到消失 |
| Busy | 保留尺寸，文案变“保存中…” | 禁止重复提交；危险请求时禁止关闭弹窗 |
| Error | 图标＋中文原因＋重试 | 不只变红，不清空已有可用数据 |
| Empty | 说明没有什么及下一步 | “暂无照片”和“照片加载失败”严格区分 |

普通路由沿用现有约定；播放器展开固定方向为下→上280ms、收起反向220ms，无弹跳过冲。完整状态／返回规则见Draft1.2。系统减少动画时即时切换或短淡入。Android继续统一LoadingRow/KernelScreen，不新增每页自画的骨架动画。

## 5. APP 页面结构与全局规则

### 5.1 应用外壳

```text
App shell（鉴权与隐私门控之后）
├─ Screen 内容：Main 四页 + 允许的二级页
├─ BottomChrome：迷你播放器（按状态）+ 主导航（仅 Main）
├─ FullPlayer：全屏覆盖，记住原页面与滚动位置
└─ Modal host：队列、确认、表单等，最高交互层
```

根部只管理 UI 展开状态；播放器和一起听会话不由某张 UI 卡片创建。BottomChrome 实测总高度统一传给列表／FAB；系统导航栏 inset 只加一次。旧 `LocalMainBottomPadding` 兼容迁移后再考虑更名，不能新旧 padding 同时叠。

展示规则：Main、音乐馆、相册列表、普通设置可显示迷你条；全屏播放器、照片查看、裁剪、照片选择、登录注册绑定、强制隐私同意与网易云登录 Activity 不显示。键盘打开时隐藏底部播放条／导航释放输入空间，输入页用 IME inset；收键盘后恢复。隐藏不隐式停止音频；退出账号／解绑音乐等仍执行原业务清理。

返回优先级：关闭可关闭弹层 → 收键盘（按平台）→ 收起全屏播放器 → 二级页 BackHandler/BackAction → 非首页主tab回主页 → 主页原有双返回退出。危险操作busy不被这条链绕过。

### 5.2 A01 主页 / NowScreen

目的：三秒看见“对方近况、信息是否新鲜、可以做什么”。

布局：标准顶栏 → 双人关系区 → 伴侣状态 → 互动操作 → 本机状态／提示。

- 双人关系区Raised、内边16；头像48，中间关系文案；纪念日数字28～32，缺日期时给设置入口，不显示虚假天数。
- 伴侣状态区：昵称18、更新时间14；电量／充电／网络按两列或自动换行。昵称长时允许两行。SSID或前台应用属于敏感信息，保留原共享／权限逻辑。
- 同组状态使用平面分隔，不给每个数字再套凸起卡片。低电量是小警告标签，不把整张卡刷红。
- 互动按钮两列，实际可用动作从现有 ActionCards 复用；冷却、撤回、请求失败保留原语义。
- 未绑定：关系引导代替伴侣区；本机状态仍可用。连接失败保留旧数据并明确标旧，不能所有格子变0。
- 演示模式持续显示“演示数据”，不伪装真实在线。更新时刻复用 StatusFreshness，不自己写一套阈值。

### 5.3 A02 待办 / TodoScreen

顶栏操作 → 内凹搜索 → 现有筛选 → 未完成／已完成内容。勾选触达48，标签多行；截止时间与提醒状态放辅助行。完成态除了颜色还需勾选与文字样式，保留撤销机制（若当前支持）。

新增沿用现有 FAB，BottomChrome 统一抬高；不要把“添加”和全屏播放器按钮放在同一位置。保存失败保留输入，网络重试不重复创建。既有分页继续 PagingMerge；闹钟权限不足显示设置路径，不假装提醒已安排。

### 5.4 A03 发现 / DiscoverScreen

目的：进入已有双人活动。相册、音乐为主入口，版面两列／窄屏一列；一起听可作为音乐入口的辅助动作，也保留兼容入口。每个入口一行说明，无大段宣传。

功能开关关闭则按现有产品规则隐藏或不可用并说明；不能用新导航绕过门控。“一起看”当前占位，不画成已上线的视频功能。

### 5.5 A04 相册列表 / AlbumListScreen

标题＋创建 → 相册列表／网格（沿用已有信息）→ 未归类、回收站、这一天入口。建议两列相册，封面1:1、名称最多两行、张数14sp；无封面用带相册图标的中性底色，不伪造默认照片。

拟态只用于页面操作和封面容器外层轻边缘，不给每张照片大阴影。无相册时引导创建；有相册无照片时说明“还没有照片”；失败显示重试。

### 5.6 A05 相册详情 / AlbumDetailScreen

顶栏名称与上传 → 简要数量 → 上传任务状态（有任务才出现）→ 照片网格。390dp建议3列，间隙4；320dp和大字体可改2列。选择态采用勾选和蓝边，选择工具栏替换普通操作，不同时堆两层。

上传必须逐项展示处理中／成功／失败，重试只处理失败项，不因列表刷新吞掉任务。新增进度若原接口只有阶段状态，先显示阶段和完成张数，不发明百分比。删除相册文案准确说明照片回到未归类；删照片、清回收站是另一种后果。

### 5.7 A06 看图／选图／裁剪／回忆

- PhotoViewerScreen：照片最大化，控制区可隐藏，暗色衬底；滑动、缩放、评论点赞等已有能力保留；不叠拟态相框遮挡图片。
- PhotoPickerScreen：相册来源／系统相册动作触达48；多选序号清楚，底部确认避让系统栏，不显示迷你条。
- AvatarCropScreen：裁剪预览与确认区分层，遮罩不得覆盖触控；bitmap清理和缩放逻辑不动。
- RecycleBinScreen：恢复蓝、彻底删除红；剩余天数来自可靠数据，未知时不显示“0天”；批量结果可核对。
- OnThisDayScreen：用日期标题组织照片；关闭功能时尊重服务端设置；没有历史照片是空态而非错误。

### 5.8 A07 音乐馆 / MusicHomeScreen

这是“选歌页”，不是播放器控制台。已登录：顶栏音乐＋账号设置 → 内凹搜索框 → 搜索／收藏分段 → 历史或歌曲列表。未登录：同一页用紧凑引导提供现有网页登录／扫码绑定，不显示不可用假收藏。

- 搜索框高至少52，提交键48；搜索词长度沿用当前80限制，不在设计里放宽。
- 歌曲行至少72，封面48×48，歌名16、歌手14、右侧操作48；整行播放与更多按钮独立命中。
- 歌名两行上限，省略后在详情可查看；正常列表不滚动跑马灯。
- 搜索结果、收藏、账号状态、歌曲解析状态分别建模，不能一次搜索让播放键进入loading。
- 收藏失败回滚图标并保留原因；解析失败不应把“正在播放”指示移动到未成功的歌曲。
- 当前已有队列和歌词能力要保留；新增筛选、歌单编辑、历史播放记录不是默认范围。

### 5.9 A08 全屏播放器 / 拟新增 FullPlayerScreen

视觉中心：封面，而非旋转唱片。390×844基准可用高度扣除系统栏后排布：顶栏56、间距16、封面最大288、信息区约64、进度约48、主控制72、辅助操作48、其余留白自适应。不把这些高度相加后强塞进所有手机。

宽度规则：主体左右24；封面边长=min(可用宽-48, 288, 高度预算允许值)。可用高度不足约700或字体≥1.3时先缩封面至160～220；再不足时主体可滚动，核心控制可达。横屏／宽度≥600采用封面与控制双列，但不能强制手机横屏。

顶部：收起48／“正在播放”或“一起听”／更多48。封面8圆角，轻Raised；空封面灰底音乐图标。歌名22/30、两行，歌手14/20，收藏48。

进度：轨道视觉4～6、触达高度48；滑块视觉16～20。拖动期间显示预览时间，松手提交seek；服务端或播放器更新不能抢回正在拖动的拇指。未知时长禁用seek并显示“时长未知”，时间不能除零。

控制：上一首48、主播放72×72圆角16、下一首48；两侧间距24。全部使用图标，不显示“上一首／下一首”按钮文字，保留中文无障碍标签。辅助行播放模式／歌词／队列各48，播放模式在引擎已支持模式间切换，不重复放循环与随机按钮；具体图标与状态见Draft1.2。320dp不能将按钮挤成32dp。

封面／歌词以显式按钮切换。歌词22～26，当前行用text，其他行用secondary，不降到难读；无歌词“暂无歌词”、加载失败“歌词加载失败·重试”。手动滚动后停止自动追随，给“回到当前”按钮。

队列弹层最大约可用高度75%，底部安全区独立消费；空队列显示提示。用稳定ID；如允许重复歌曲需独立队列项ID，不用歌曲ID作重复key。弹层关闭恢复打开按钮焦点。

加载、暂停、播放错误分别表达。音频在缓冲时不要用虚假唱片旋转暗示已播放。打开页面不能自动重新播放／重新解析同一歌曲。

### 5.10 A09 迷你播放器 / 拟新增 MiniPlayer

基础64高（是minHeight），左右16、与导航间8。封面40，歌曲区域可收缩，暂停触达48；整个主体作为“展开播放器”按钮，但不嵌套另一个可点击控件造成事件冲突。

点主体从底部向上展开全局完整播放器，暂停按钮不触发展开。原页、tab和滚动保持；收起反向返回，不先跳音乐馆选歌列表。遵守Draft1.2的动画、焦点与重复点按规范。

首轮只放封面、歌名／歌手、播放暂停，不放上下一首、进度条、关闭、歌词和音量全家桶。播放失败副行显示“播放失败·点开处理”。没有曲目完全不占位；暂停有曲目时保留。收起不等于停止；停止放全屏更多菜单。

### 5.11 A10 一起听 / ListenTogetherScreen → 会话入口＋播放器模式

保留现有房间创建／加入、角色、可控设置、REST恢复、WS和心跳。不将当前 `DisposableEffect` 原样复制到全屏页，否则收起就断线。

视觉：播放器顶部下方一行双方头像／成员信息＋状态，点击展开房间设置。不要凭连接成功显示“毫秒同步”；如果当前数据只有成员数，就显示成员数，头像／在线状态必须来自真实可用数据。

| 房间状态 | 文案 | 可操作 |
| --- | --- | --- |
| 未进入 | 和伴侣一起听 | 创建／加入，沿用现有入口行为 |
| 正在进入 | 正在进入一起听… | 防重复提交，可按现有安全取消策略返回 |
| 等待 | 等待对方加入 | 房主选歌；不伪造第二人头像在线 |
| 已连接 | 已连接一起听 | 按 host 或 allowMemberControl 判可控 |
| 恢复中 | 连接中断，正在恢复 | 不显示同步成功；控制请求失败需反馈 |
| 无权限 | 当前由房主控制 | 播放／seek／切歌禁用，并给解释 |
| 已关闭 | 房间已关闭 | 清除房间态；本机继续／暂停策略显式定义 |

建议房间关闭时暂停本机播放并显示“房间已关闭，可继续单独听”；这是新UX决策，实施时与现有行为比对并写测试。不得偷偷重建房间。成员加入、离开不自动夺取音频控制。

### 5.12 A11 我的与二级设置

SettingsScreen：头像／昵称→关系→外观→音乐→权限与保活→关于，沿用实际项目分组，避免重复出现三处退出。组容器Raised，行Flat；行标题16、摘要14、箭头固定位置。

AppearanceScreen：保留浅／深／跟随系统及既有外观功能；用小样本展示当前材质。首轮不额外加“光源角度／阴影强度”用户滑杆，减少组合爆炸。

MusicSettingsScreen：绑定状态、播放偏好按原能力展示；解绑音乐明确影响本机账户／播放，不能误写为解绑情侣关系。ProfileEditScreen保存失败保留草稿；KeepAliveCheckScreen逐项解释权限作用和降级后果，不伪装获得系统权限。HistoryScreen显示真实时间与缺失值，继续去重分页。

AboutScreen／更新弹窗／ChangelogFormatter：版本、变更记录、更新进度保留；不因为重设计改变版本号或安装链路。PrivacyConsentScreen长文可读、选择明确；不以拟态弱对比隐藏拒绝或诱导同意。

### 5.13 A12 登录、注册、绑定及独立登录 Activity

LoginScreen／RegisterScreen：一列主体，最大宽420，输入框Inset但有可靠边界；错误贴近字段，全局错误在提交区；键盘不盖按钮；不把口令当普通文本。BindScreen分别表现创建邀请、输入邀请、等待与失败，不在截图中放真实邀请码。

NeteaseWebLoginActivity：仅修改自有外壳、返回与状态展示，第三方网页不注入拟态CSS，不改变认证流程。NeteaseQrLoginActivity：二维码保持黑白对比、完整静区、不加柔光遮罩，过期和扫码状态清楚；这些功能不是 Compose 主 Screen，也必须列入覆盖。

系统权限页、系统照片选择器、通知栏由系统控制：仅调整可控文案与自有容器，不声称能把系统UI全部拟态化。RemoteViews继续XML，系统MediaSession继续原生通知。

## 6. 后台完整页面规划

### 6.1 公共外壳与组件

桌面侧栏224、顶栏56、内容边距24、区块间24；1024～1279侧栏可折叠；低于1024用抽屉导航；低于768边距16、操作区换行。不要通过页面缩放塞入桌面表格。

标题区左：标题与最多一行说明；右：本页真正的主操作。筛选区支持换行、清除筛选和当前条件；数据区Flat置于轻Raised容器。详情抽屉桌面480～560，手机全宽。表格外层容器允许局部横滚，页面本身不得横向溢出；窄屏关键字段可改卡片摘要，操作仍可达。

所有弹窗有标题、后果、取消与确认；关闭按钮48触屏命中。危险操作确认默认延迟1s、busy不允许遮罩／Esc／关闭图标关闭。前端需新增统一封装，不宣称Element Plus默认具备这些行为。表单有未保存草稿时离开提示；不将只读字段伪装可编辑。

保留 i18n，不能在整站混入大量硬编码中文。桌面菜单文字至少14，选中标记除了光影还应有颜色和位置标识。loading保持表格尺寸，失败不显示“暂无数据”。

### 6.3 权限矩阵以服务端为准

| 能力 | 普通 admin | super |

| 相册、照片元数据／缩略图、存储统计、回收站清空、管理员管理、敏感settings读取 | 不发请求、不先拉后藏 | 授权范围内执行 |
| 运行参数 | 用runtime-settings；写仅非敏感允许项 | 含敏感项，仍受范围检查 |

当前部分菜单meta包含admin，不能据此把敏感tab中的按钮放给admin。新稿应对菜单、tab、请求和动作做一致门控；最终403仍由服务端保障。

## 7. 设计交付验收，不以“感觉完美”结项

必须提交：组件状态板、六张关键正常态＋对应暗色稿（主页／音乐馆／全屏播放器／相册／后台看板／日志中心）、一起听关键异常态、全页面覆盖清单、实际截图与未解决项。HTML示意仅用于方向对齐，不代替这些生产验收。

- 320dp、字体1.5下没有按钮重叠；字体2.0仍可操作，可滚动，不承诺所有内容首屏容纳。
- 浅／深均无透明图片位、隐形输入边界、光影反向、页间不同圆角。
- 全局播放器不挡最后一项／FAB；主tab到二级页切换不重建播放；普通返回不退出房间。
- Room模式迷你条／全屏／系统通知的控制权限一致；真正没接通时绝不显示已同步。
- 所有页面有真实加载、空、错和重试，错误刷新不抹去旧数据；异步响应不覆盖新筛选。
- 普通admin访问敏感页面无内容泄漏，连预取都不发生；super看缩略图保留审计和响应头。
- 默认主题保留品牌约束；对比冲突公开记录，不虚报AA。
- 真实一加15验证滑动、播放、切后台、来电音频焦点、锁屏通知、图片OOM路径、返回与观感。

工程任务、可执行测试和分批交付要求见 IMPLEMENTATION.md。任何未验证项必须标“待验证”，不能写“全部完美适配”。
