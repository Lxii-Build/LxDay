## 2. 暗色：从偏蓝发亮，改为安静石墨灰

### 2.1 色值与光影

暗色不做浅色的机械反转。大面积去蓝，蓝色只留在主操作、选中和进度；表面靠少量明度差形成层级。以下是设计初值，须用最终合成结果和真机复核，不宣称已完成全部对比度验收。

| Token | 新暗色 | 具体用途 |
| --- | --- | --- |
| canvas | `#202328` | 页面底；不要再盖半透明蓝色蒙层 |
| surface | `#272B31` | 卡片、按钮、mini主体 |
| elevated | `#32373F` | 弹窗、抽屉、浮层，靠颜色抬高 |
| text | `#F1F3F5` | 正文、歌名、主图标 |
| textSecondary | `#B8C0CB` | 歌手、时间和辅助说明，不额外降alpha |
| line | `#424851` | 普通分隔线；不承担交互轮廓的唯一识别 |
| controlBoundary | `#8893A0` | 输入、焦点之外仍需要辨识的控件边界 |
| link | `#9CBFFC` | 链接、选中说明、焦点；避免满页亮蓝文字 |

品牌蓝`#277AF7`、品牌红与语义不变。白字蓝／红小文本对比度的原有例外仍未解决，不能因为背景换暗色就声称达标。

- Raised：右下`3 3 8 rgba(0,0,0,.28)`，左上`-2 -2 6 rgba(255,255,255,.04)`。
- Inset：内部右下`2 2 5 rgba(0,0,0,.32)`，内部左上`-1 -1 3 rgba(255,255,255,.035)`。
- Floating：`0 8 20 rgba(0,0,0,.28)`＋内部顶边`0 1 0 rgba(255,255,255,.04)`；不是发光描边。
- 避免蓝色阴影、白色外发光、纯黑凹坑和每行一圈硬描边。上边高光是材质点缀，不作为按钮可辨性的依据。
- 普通列表、表格仍Flat；卡片与按钮内部不再套多层Raised。封面、角色保留原色，不能用统一暗滤镜压坏素材。
- 暗色玻璃导航提高基底实度以保证文字，保留现有结构；不得为了拟态去掉系统inset。
- pressed采用低位阴影／内凹反馈，不闪亮白边。disabled不再叠第二次全局opacity导致文字消失。

### 2.2 要交什么样的视觉证据

必须同一组数据同时展示浅／暗：首页（含角色）、完整播放器、相册、后台表格、导入表单、危险弹窗。检查大面积是否发蓝、投影是否像脏边、输入是否看不出可点、封面与角色是否融成黑块。暗色截图不能只拍一个空白页。

先把公共tokens与材质样板交用户确认，再铺全页面。HTML仅展示方向，Android颜色还需正确接入miuix主题，不能在每个页面硬编码一套灰色。

## 3. Live2D：三个入口、一条清楚的资源流

```text
后台「资源管理 / 陪伴角色」（超管）
  选择本机ZIP → 上传草稿 → 校验与授权记录 → 发布可选版本
                                                     ↓
APP「我的 / 外观 / 陪伴角色」 → 资源库 → 下载并本机再校验
                       └→ 从文件导入 → 系统文件选择器ZIP
                                            ↓
                             本机预览与校准 → 用户启用
                                            ↓
                           主页伴侣状态之后的陪伴角
```

本机导入**不反向上传云端**，后台也不能查看某用户导入的私有模型。后台发布只是提供选项，不自动替换用户当前模型。两个来源共用本机校验、预览与激活机制。主页位置、Java SDK、GL合成、离屏停渲染与安全预算沿用1.1。

### 3.1 APP管理页：不是只有一个“上传”按钮

入口一：主页陪伴角的“管理角色”。入口二：“我的→外观→陪伴角色”。两处到同一管理页，收起／返回回原入口，不开第二个渲染器。未配置角色时外观入口始终可见。

页面使用KernelScreen＋BackAction＋BackHandler，16页边、16圆角、48触达。结构：

1. 顶栏“陪伴角色”。
2. “在主页显示”开关，说明“仅显示在主页，不会悬浮在其他页面”。关闭只是隐藏，不删除模型。
3. 当前角色：预览舞台minHeight200，名称最多两行、来源（本机导入／资源库）、版本、占用大小、“当前使用”状态；无模型时为明确空态。
4. “我的模型／资源库”分段，微凸选中＋持久选中语义。我的模型列名称、大小、导入时间和是否当前；普通行Flat，选中不用整行发蓝。
5. 固定可找的主操作“导入模型包”，带文件图标＋中文，不改成无人认识的单个加号。资源库提供刷新与下载状态。
6. 点模型进入详情／预览：缩放、上下位置、重置位置、启用；更多菜单含重命名／移除本机副本。位置校准不修改原manifest或纹理。

一次只启用一个，可保留多个本机模型。新增本机目录总容量与模型数量预算（建议首轮10个、300MiB，可在实测后收敛），与单包上限分开；到顶明确提示管理空间，不能自动删除正在用或其他用户主动保留的模型。资源库“下载后启用”仍须先预览确认，不能下载完成立即顶替。

短屏或大字体优先缩预览舞台并允许页面滚动，操作不压到系统导航栏。加载仍用统一LoadingRow；无资源“资源库暂无角色”，断网“资源库加载失败·重试”，本机模型在断网时仍可管理。

### 3.2 Android文件选择器：明确到实现细节

使用Android系统Storage Access Framework，`rememberLauncherForActivityResult(ActivityResultContracts.OpenDocument())`选择单个ZIP。这是文档包，不复用PhotoPickerScreen；项目照片选择逻辑保持原样。官方说明该用户选择文件流程不需要全盘存储权限。[Android SAF文档](https://developer.android.com/training/data-storage/shared/documents-files)

- 主按钮“选择ZIP文件”，提示“需要model3.json、moc3和全部贴图；支持普通未加密ZIP”。文件选择器由系统绘制，App不能把它改成拟态；拟态覆盖自己的按钮、结果摘要和导入预览。
- MIME优先ZIP常见类型；若供应商错误标注导致找不到文件，提供明确的“显示所有文件”重试入口，选择后仍按真实格式与结构校验。扩展名和MIME都不是安全保证，不开放目录树权限来绕过。
- Launcher无条件注册，回调只取得Uri并交给导入owner，IO在后台线程。用户取消（null Uri）静默回管理页，保留旧选择，不显示红色失败Toast。
- 通过ContentResolver打开流，不把`content://`转换成磁盘绝对路径，不扫描下载目录；先确认流打开成功，不踩`?.use{返回null} ?: error`旧坑。
- Document元信息仅供提示，名称需清洗，大小可能未知；流式计数是最终上限。云盘文件可等待和取消，不假定立即可读或可seek。
- 选取后马上流式复制到本次私有staging，关闭源流；成功后不再依赖外部Uri，首轮无需长期保留访问权限。进程在复制中终止时清理不完整staging，提示重新选择，不声称后台继续完成。
- 获取失败显示“无法读取所选文件，请重新选择”；格式错给完整模型包说明；不能将权限／磁盘满／取消都写成“文件损坏”。错误分类和路径校验做成纯策略测试。
- 选择后先出现文件摘要：名称、输入大小（未知时直说）、模型检测阶段；用户可取消校验。关键激活的短事务期间busy并防重复，取消不得删除源文件。

首轮状态流：`未选择→复制→校验→待预览→预览就绪→启用中→已启用`；任一步失败保留旧模型并提供重试／重新选择。取消与失败是不同终态，进度未知就用阶段文案，不编造百分比。

### 3.3 后台角色库：页面与导入表单

新增菜单“资源管理→陪伴角色”（若实际路由只有平级分组，按现有约定落地，不为了菜单另建整套框架）。本规范定为**超管全权限，普通admin无入口、无请求、服务端403**；资源上传／发布会影响客户端处理的二进制模型，不能按“不含密钥”放宽。

桌面标题24/32；左标题和数量，右“导入角色”品牌蓝按钮。下方关键词、状态筛选、刷新；表格使用ArtTable，列为：静态封面64、名称／版本、模型兼容信息、ZIP大小、校验状态、发布状态、更新时间、操作。封面是资源素材，不是用户相册；无封面有占位，首轮后台**不运行未知模型、不嵌入WebGL预览**。

手机≤768：筛选折行，主要操作48触达；表格自身横滚或按既有小屏方案，不让全页面横滚。导入／详情抽屉桌面宽560左右、窄屏占满可用宽，底部操作条避让安全区。

导入抽屉顺序：

1. **选择模型包**：实体文件按钮＋可选拖放区域。使用Element Plus Upload，单文件、禁自动上传、选中只加入待提交列表。用户点“上传并校验”才通过项目认证请求上传；UI的accept不是服务端校验。[Element Plus Upload](https://element-plus.org/en-US/component/upload.html)
2. **基本信息**：名称（建议1～40字符）、作者（建议≤80）、描述（建议≤300）、版本显示名（≤32）、可选封面。规范化/长度在服务端重复校验，不直接v-html展示描述。
3. **授权信息**：来源链接、许可说明、是否允许本应用内下载分发、确认人／确认时间；界面提示“允许本机使用不等于允许通过后台分发”。仅打勾不是法律授权证明；发布前必须完成实际授权核验，未确认可以留草稿不能发布。
4. **选择文件摘要**：名称、大小、待上传状态，“重新选择／移除”清楚可见；刷新／离开前若有未保存输入要提示。取消系统文件对话框保留原草稿，不自动移除已选文件。
5. **上传并校验**：上传可显示真实已传字节进度，服务端处理显示阶段；文件列表中的“上传完成”不等于“可发布”。校验错误按项列出，不用一条“操作失败”吞掉原因。
6. **结果**：入口文件、引用资源数量、贴图合计像素、SHA-256、兼容目标、失败原因；状态“静态校验通过，仍需客户端真实渲染验收”。上传成功不会自动发布。

封面若接受单独PNG/JPEG，走独立限尺寸解码和缩略化（建议输入≤2MiB、≤4M像素、输出≤384边），后台照片隐私通路不能复用。服务端不为生成封面自动执行moc3、包内HTML或脚本。没有封面可使用统一占位，不阻塞合法模型。

### 3.4 生命周期与权限

首轮采用不可变资源版本，名称等展示元数据可更新；更换ZIP一定创建新版本、重新校验。状态区分`draft / validating / ready / published / withdrawn / invalid`，状态转移在服务端白名单执行，不能把任意status值直接落库。

- 草稿→上传校验→ready：仅通过结构与预算检查，还不是SDK实际渲染保证；记录验证策略版本，策略改变后可要求重检。
- ready→published：需要有效授权记录、支持SDK版本记录、管理员真实客户端渲染验收记录，且内容未变。发布按钮清楚说明“用户可从资源库下载，不会自动启用”。
- published→withdrawn：从资源库隐藏并禁止新下载；已经下载到本机的副本默认保留，不远程删除用户数据。紧急安全撤销机制需单独产品决定，首轮不暗加远程擦除。
- withdrawn→published：重新检查授权、内容hash、验收状态，不能绕过发布门槛。
- 物理删除：已下架且无进行中的校验／下载引用才可清理；有明确后果、红色确认、1秒延迟与busy。不能把下架等同彻底删除，也不能删除整个资源根目录。
- 普通admin、未登录用户、过期token不得读写管理接口；App资源库仅给已认证用户已发布版本。前端隐藏不替代服务端鉴权。
- 审计只记录动作、角色ID／版本、结果与必要hash等白名单字段，不记录原始包、上传绝对路径、临时签名／token或完整授权文书。

### 3.5 服务端方案（全部为拟新增，不是当前已有API）

接手AI先核对`server/admin.go`、现有客户端路由、认证中间件、上传限制、存储抽象、settings及迁移先例，再定最终名称。以下是路由相对各自**现有鉴权组**的资源后缀提案，不假设它们现在可调用：

| 管理组接口提案 | 用途 |
| --- | --- |
| `GET /companion-models` | 分页筛选版本元数据，不读文件系统全目录来分页 |
| `POST /companion-models` | 建草稿元数据，返回ID；按幂等键防重提交 |
| `POST /companion-models/{id}/package` | 上传ZIP到staging，返回校验任务／状态；不自动发布 |
| `GET /companion-models/{id}` | 读取详情与校验结果；页面关闭停止轮询 |
| `PATCH /companion-models/{id}` | 更新允许的草稿／展示字段，带revision防覆盖 |
| `POST /companion-models/{id}/publish`、`.../withdraw` | 显式动作，检查状态、授权、revision并审计 |
| `DELETE /companion-models/{id}` | 仅符合删除条件的版本；精确清理、可核验结果 |
| App组 `GET /companion-models` | 仅已发布的兼容选项；未知兼容性不得标“保证支持” |
| App组 `GET /companion-models/{id}/package`、`.../cover` | 鉴权资源代理；路径由ID映射，不接收任意磁盘路径 |

需要的记录包括：内部ID、逻辑角色ID、不可变版本、name/author/description、model入口相对路径、包/封面内部storage key、SHA-256、压缩／解压大小、总纹理像素、兼容目标、状态、validation报告与策略版本、授权／真机验收记录、created/updated/published时间、revision。storage key和私有授权细节不在App DTO；JSON字段类型和错误码先写契约与测试再实施UI。

服务端安全与资源处理：

- 资源存储放现有数据根下的独立受控子目录，不改compose/.env，不写进公开`/upload`或`/uploads`，不复用私密相册的数据表/鉴权代理语义。按模型ID鉴权传输，不下发服务器绝对路径。
- 上传使用受控流、输入上限、任务并发闸门、磁盘配额、取消和超时；不能将50MiB ZIP一次读进内存，不受控地为每请求启动常驻协程。现有HTTP/反向代理体积上限可能不同，先测；受限则收敛模型预算或报告部署决策，不能擅自改生产代理。
- 1.1的路径穿越、条目、实际解压字节、JSON、引用和纹理预算在服务端独立实施；不相信浏览器预检。服务端不需要Cubism native渲染，通过静态检查也不证明模型一定能显示。
- 暂存任务有容量上限、定期清扫、超时和启动恢复；进程被杀后的validating不能永久悬挂。过期清理返回RowsAffected并留英文日志；不得在rows循环中查询配置。
- 建表→补列→索引，旧库升级测试；新增可调上传／库存限制统一runtimeSettingSpecs且读取端贯通，按破坏力定Super。可下发“有效可导入上限”，客户端仍取服务策略与本机安全硬上限的更小值。
- 提前失败走fail/afail排空请求体；检查所有Scan/DB/文件写入/关闭错误。验证文件先落完整不可变版本再让DB发布指针可见，事务失败登记孤儿文件待精确清理，不能指向半个ZIP。
- 传输走当前可信服务origin和认证请求；下载／封面响应使用明确Content-Type、nosniff、私有缓存策略，不把token塞URL。原始包建议no-store；下载到私有本机库是用户主动持久化操作，与HTTP缓存分开。

### 3.6 APP资源库下载与激活

使用现有认证网络层下载，不直接把带token的URL交给第三方通用下载器。请求只走可信资源代理，禁止任意外域重定向带走凭据；离开页面可明确取消，首轮不申请新后台下载服务权限。

下载写staging，流式计算SHA-256并对比可信API给的版本hash，同时实施本机大小与结构检查。hash用于检测完整性，不能证明作者可信或代替授权。超预算、下载中断、hash不符、不兼容时不显示“已导入”，旧模型保持可用；用户主动重试。首轮可不做断点续传，文案必须如实说明重新下载。

数据库发布版本号不变时内容hash也必须不变。客户端可提示“有新版本”，由用户下载→预览→启用；不在主页启动时自动拉大包。删除本机副本不会删除后台资源；后台下架不会悄悄移除本机副本。

## 4. 迷你播放器 → 全屏播放器：下起上展

### 4.1 用户应看到的连续过程

当前页底部mini的封面／歌名主体可点，右侧播放暂停是独立按钮。点主体后，完整播放器**从屏幕底边向上进入，覆盖当前页面**；它就是音乐馆所用的完整播放界面，不要先导航到音乐馆搜索页、再做第二次跳转。

主tab不变，原页面和滚动位置保留。收起回到原页面、原位置、同一首歌的最新进度；开合不会重新解析歌曲、自动重新播放、切队列或退出房间。从音乐馆、主页、相册允许入口打开的都是同一个全局player UI层。

### 4.2 动效参数（产品规定的初值）

| 阶段 | 参数与要求 |
| --- | --- |
| 展开 | 全屏容器translationY从自身全高`H`到`0`，280ms，cubic-bezier(.2,0,0,1)，不弹跳过冲 |
| 收起 | 当前Y到`H`，220ms，cubic-bezier(.4,0,1,1)；结束后移除全屏层 |
| 底部mini／导航 | 展开前80ms内淡出并禁交互；收起末段约100ms恢复，避免同屏两组可操作控件 |
| 背景 | 原页保留，不缩成小卡，不加封面大模糊；可用极轻scrim≤.12，不抢主体 |
| 封面与文字 | 首轮跟随容器移动，不强求跨层共享元素变形，避免额外Bitmap峰值 |
| 减少动画 | 尊重系统动画缩放／关闭与辅助设置，直接切换或≤100ms短淡入，不强制280ms |

Android通过外壳overlay的Compose状态驱动offset/动画，具体API按已解析Compose版本搜索确认；动画尺寸来自实测容器高度，不能写死844px，也不能误把px当dp。坐标覆盖应用内容区域并正确处理edge-to-edge；状态栏和导航栏inset消费一次，底部控件始终留安全区。

首轮不要求拖拽交互才能验收。若做下拉收起，只在顶部把手／标题专用区域捕获，歌词滚动和进度滑块不触发关闭；拖动距离达到播放器高20%或向下速度超过1000dp/s时收起，否则回弹至展开位。这些也是待真机调校初值，不与LazyColumn争夺整屏手势。

### 4.3 状态、返回与连续点按

使用清楚的`Collapsed / Expanding / Expanded / Collapsing`UI状态，快速重复打开合并为一次，不叠多层播放器。动画中用户按返回应从当前位置收起；不能等动画结束后突然再开一层。切主题、旋转、窗口尺寸变化根据目标态重算几何，保持曲目与会话不变。

全屏打开后底层页面不接收点按／无障碍焦点。返回优先关闭歌词／队列等子弹层，再收起播放器，然后才是原页返回；busy危险弹窗的不可关闭规则仍优先。收起后焦点回mini主体或合法打开按钮；播放器展开触发时不移动主tab选中项。

NeteasePlaybackManager继续单例事实来源；一起听WS/心跳所有权必须从ListenTogetherScreen迁出后再做全局UI。全屏与mini只发同一套用户命令和权限检查，动画生命周期不能创建／销毁引擎。没有播放权限的成员不能通过mini、完整页或通知绕过。

### 4.4 动效验收场景

- 主页滚动到中段→点mini主体→由下向上打开→点收起→原页原滚动；曲目／进度连续，mini右侧暂停不触发打开。
- 音乐馆选歌→打开同一个完整页；在一起听中重复同样操作，socket／心跳不因开合重建。
- 连点展开10次只有一个界面；动画中返回、旋转、切暗色，无残留遮罩／双层UI。
- 100次开合检查player实例仍1、会话／线程不线性增长；测量慢帧，不以网页动画顺滑代替一加15真机证据。
- 320宽、横屏、大字、无封面、未知时长、正在缓冲、播放失败、系统减少动画各验一次。

## 5. 播放操作用图标，语义不能消失

“不用文字”指可见按钮表面，不代表删掉中文无障碍标签。歌名、歌手、时间、状态、错误和管理表单继续中文文本。主播放键72×72、其他48×48最小触达，图形24dp左右、主播放图形28～32dp，16圆角规则不变。

| 操作 | 可见图形语义 | 无障碍／tooltip文案 |
| --- | --- | --- |
| 收起 | 向下chevron | “收起播放器” |
| 上一首／下一首 | 三角＋端点竖线，不用快退／快进双箭头 | “上一首”／“下一首” |
| 播放／暂停 | 单三角／两竖条 | 跟随真实状态为“播放”或“暂停” |
| 播放模式 | 队列循环双箭头；单曲在图标内加1；随机用交叉箭头 | “播放模式：列表循环／单曲循环／随机播放” |
| 歌词 | 库内歌词／文本行近似图标 | “显示歌词”，展开后“返回封面” |
| 队列 | 音符／列表近似图标 | “打开播放队列” |
| 收藏（原有能力） | 对应收藏图标，填充／选中形态 | “收藏歌曲”／“取消收藏” |
| 更多 | 省略点 | “更多播放选项” |

辅助操作首轮是一枚**播放模式**按钮在已有支持模式间轮换，不同时放一枚“循环”再放一枚“随机”制造相互冲突。若实际播放引擎不支持某模式，先保留已支持集合，不能只换图标假装已启用；确需新增模式作为独立逻辑任务和单测。状态不只靠蓝色区分：图标形状、单曲1标识与读屏stateDescription一致。

实现必须从本仓库miuix0.9.3实际可用图标中选，先搜源码／已解析AAR并编译。**表格是视觉语义，不是可直接import的类名**，不得编造MiuixIcons.Previous/Repeat等不存在符号；extended用MiuixIcons，basic用MiuixIcons.Basic。缺精确图标用已验证近似者，仍不混入Material图标。HTML用原创SVG说明形状，不是授权生产绕过图标体系。

封装共享`LxIconAction`（建议新名，先实现），内部保证48触达、按压／禁用／焦点、contentDescription、状态与busy防重；不能各调用点自行加padding。在一起听无权限时保持必要轮廓，点击行为按既有业务给原因或禁用并有可读说明，不能直接发命令。

网页预览／后台涉及此类图标按钮时加aria-label，tooltip对键盘也可用；图标内部SVG设aria-hidden，避免重复朗读。“上一首”文字不得在点按后替换进图标按钮，反馈走独立状态区。
